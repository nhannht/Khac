# Oracle test data

This directory holds ported test CASES used as a correctness oracle - not test
code, only the facts a reference implementation's own tests assert (input text,
reference date, expected date/components). See the root `NOTICE` for the
project-wide prior-art credit.

## EN/

Ported from [wanasit/chrono](https://github.com/wanasit/chrono) (MIT), the
`test/en/*.test.ts` files, at the revision fetched for this port. `chrono`'s own
test code (the `testSingleCase`/`testUnexpectedResult` harness, its Jest custom
matchers) is not copied - only the inputs, reference dates, and expected
date/component values its tests assert are ported, as data.

- `OracleTypes.swift` - the engine-agnostic schema (`OracleCase`,
  `OracleComponents`, `OracleDate`, `OracleExpectation`, `OracleMode`). No
  dependency on Khac's `KhacLocale`/`ParsingComponents` types, so this data
  compiles standalone.
- `*Cases.swift` - one file per originating chrono test file (e.g.
  `WeekdayCases.swift` from `en_weekday.test.ts`), each exporting a `let
  <name>Cases: [OracleCase]`. Generated, not hand-written - see below.
- `AllCases.swift` - aggregates every table into `enOracleCases`.
- `ENOracleTests.swift` - runs `enOracleCases` against the real engine
  (`Khac(localeInstances: [ENLocale()]).parse(...)`).
- `ENOracleSmokeTests.swift` - a lightweight structural check (case count,
  non-empty inputs) independent of parser implementation state.

### What was filtered out, and why

Of 577 raw chrono EN cases, 563 were ported. 14 distinct cases were excluded
(15 reason-instances below - one case, `"Want to meet for dinner (5pm EST)?"`,
triggers two of these at once: it embeds a timezone abbreviation AND asserts
nothing else portable):

- **5** - the input text embeds a named timezone abbreviation (UTC, JST, EST,
  ...). Khac's v1 generic parsers do not include a
  timezone-expression parser, so these are out of scope for now.
- **4** - `chrono.en.GB`, chrono's day-first English variant. Khac's `ENLocale`
  is month-day order for English; day-first is a
  different locale option, not modeled by this locale. Deferred, not dropped.
- **4** - the source test asserted nothing portable (a `.toContain()` substring
  check with no reference date and no component assertions).
- **2** - the reference instant chrono's test supplied was an epoch-millisecond
  `new Date(N)` or an explicit-offset date string, neither of which is portable
  without assuming epoch/offset semantics this port did not want to guess at.

`chrono.strict` cases ARE ported (both positive and the strict-only negative
guards) - Khac's own `Options.Mode` has a matching `.casual`/`.strict` split, so
these are meaningful oracle cases, tagged `mode: .strict` in the case data.

### Regenerating

The case tables are generated by a small extraction pipeline (not checked into
this repo - it is a one-time port, not a build step): a script parses chrono's
`test/en/*.test.ts` source for `testSingleCase`/`testUnexpectedResult` calls,
evaluates the JS `Date(...)` arguments, and emits the Swift literals above. If
chrono's EN suite changes and a re-port is wanted, re-derive the same way rather
than hand-editing the generated files (they are marked `GENERATED FILE` at the
top).
